# 工具类技术规范

本规范用于指导在 LangChain 工具平台（Python 3.11+, langchain_core 工具体系）中编写可被自动验证、注册并通过 MCP 调用的工具代码。遵守本规范可以减少验证失败、运行异常和安全风险。

---

## 1. 适用范围
- 使用 `@tool` 装饰器定义的函数型工具。
- 继承 `BaseTool` 的类工具。
- 需在平台内上传、验证、执行、被 MCP 客户端调用的所有工具。

## 2. 硬性要求（提交前必过）
- 必须导入自 `langchain_core.tools` 的 `tool` 或 `BaseTool`。
- 必须提供 docstring，首句清晰描述用途，后续详细说明参数、行为、边界。
- 所有参数和返回值必须有类型注解（包含默认值的参数也要标注类型）。
- 返回值建议为可 JSON 序列化的基础类型（`str`/`int`/`float`/`bool`/`dict`/`list`）。
- 运行时不得抛出未捕获异常：需要显式捕获并返回可读错误信息。
- 不得硬编码敏感信息（Token、密码、私钥等），不得上传含明文密钥的代码。
- 代码需可重复执行，无全局共享可变状态副作用；避免在导入阶段执行耗时或有副作用的逻辑。

## 3. `@tool` 装饰器函数规范
- 结构示例：
  ```python
  from langchain_core.tools import tool

  @tool
  def my_tool(param1: str, param2: int = 10) -> str:
      """清晰的一句话概述
      
      详细描述功能、输入输出和边界情况。
      Args:
          param1: 作用与取值范围
          param2: 作用与默认值含义
      Returns:
          描述返回内容或格式
      """
      try:
          # 业务逻辑
          return "result"
      except Exception as e:
          return f"错误：{e}"
  ```
- 不要使用 `*args`/`**kwargs` 作为主要接口，需显式参数。
- 如需外部请求，增加超时与错误提示；限制非必要的 `eval/exec`。

## 4. `BaseTool` 类规范
- 最小骨架：
  ```python
  from langchain_core.tools import BaseTool
  from pydantic import BaseModel, Field
  from typing import Type

  class MyInput(BaseModel):
      query: str = Field(description="查询内容")
      limit: int = Field(default=5, ge=1, le=50, description="返回条数")

  class MyTool(BaseTool):
      name: str = "my_tool"
      description: str = "查询示例"
      args_schema: Type[BaseModel] = MyInput

      def _run(self, query: str, limit: int = 5) -> str:
          try:
              return f"{query}:{limit}"
          except Exception as e:
              return f"错误：{e}"

      async def _arun(self, query: str, limit: int = 5) -> str:
          return self._run(query, limit)
  ```
- 必须定义 `name`、`description`、实现 `_run`；`_arun` 可选但建议保留以兼容异步。
- `args_schema` 推荐使用 Pydantic 模型并为字段提供 `description`、范围或枚举限制。

## 5. 输入 Schema 设计
- 使用 Pydantic `Field` 描述含义、范围、单位、格式示例。
- 设置合理的默认值与取值约束（`ge/le`, `regex`, `enum`）。
- 避免模糊字段名：使用小写下划线，如 `start_date`、`max_retries`。
- 布尔值用 `is_*/has_*` 前缀；列表参数命名为复数。

## 6. 错误处理与返回格式
- 捕获预期异常并返回可读信息，如 `return "错误：除数不能为零"`。
- 对外部依赖（HTTP/DB）添加超时与异常捕获，返回明确的错误原因。
- 不要泄露堆栈与敏感信息；日志仅用于内部调试时再添加，默认避免 `print` 噪声。

## 7. 安全与合规
- 禁止明文凭证、固定 Token、私钥、访问密钥等。
- 谨慎使用 `eval/exec`、文件写入、系统命令；如必须，需做白名单与输入校验。
- 网络调用需考虑目标可达性和重试上限，避免长时间阻塞。

## 8. 性能与资源
- 避免在导入阶段加载大型模型或大文件；延迟加载并在 `_run` 中缓存轻量资源。
- 控制单次执行时间，必要时增加超时或分页。
- 大结果请做裁剪或分页返回，避免超长文本。

## 9. 文档与可观测性
- docstring 应包含：用途一句话、输入参数说明、返回内容格式、边界或限制。
- 对重要分支可简短注释说明（保持克制，避免注释噪声）。
- 需要调试时可使用受控日志（如 `logging`），勿默认输出到 stdout。

## 10. 提交前自检清单
- [ ] 导入使用 `langchain_core.tools` 的 `tool` 或 `BaseTool`。
- [ ] 参数与返回值类型齐全，docstring 完整且具体。
- [ ] 无明文密钥、无危险 `eval/exec`、无未捕获异常。
- [ ] 外部请求有超时与错误处理，返回人类可读的错误提示。
- [ ] 输入字段命名规范、描述完善，默认值与范围合理。
- [ ] 本地运行（或 `仅验证`）通过。

## 11. 常见错误示例
- 缺少 docstring 或首行未描述用途。
- 参数未加类型注解，或使用 `*args/**kwargs` 作为主接口。
- 返回复杂对象（如自定义类实例）导致序列化失败。
- 未捕获异常，导致平台返回 500。
- 在导入时执行耗时或有副作用的代码（如立即请求外部 API、写文件）。

## 12. MCP 兼容注意
- 平台会暴露 `inputSchema` 给 MCP 客户端；描述越清晰，表单生成越准确。
- 确保 `name` 稳定且唯一，避免与已有工具冲突。
- 返回值简洁明了，便于在聊天界面呈现。

## 13. 版本与依赖
- Python 3.11+，建议与平台同版本的 `langchain-core`。
- 避免引入重量级或罕见依赖；如必须，引入前与平台维护者确认。

## 14. 示例：良好与不良对比
- 良好：
  ```python
  @tool
  def format_phone(phone: str) -> str:
      """格式化中国手机号为 3-4-4 格式"""
      digits = ''.join(filter(str.isdigit, phone))
      if len(digits) != 11:
          return "错误：需提供 11 位手机号"
      return f"{digits[:3]}-{digits[3:7]}-{digits[7:]}"
  ```
- 不良（勿使用）：
  ```python
  @tool
  def bad(phone):
      return eval(phone)  # 缺类型注解、无 docstring、危险 eval
  ```

## 15. MCP 调用规范（开发者）
- 服务根地址：`http://localhost:8000/api/mcp`
- 主要端点：
    - `GET /api/mcp/tools`：列出可用工具（仅 valid）。
    - `GET /api/mcp/tools/{tool_name}`：单工具元数据（含 inputSchema）。
    - `POST /api/mcp/call`：通过 JSON 请求调用工具。
    - `POST /api/mcp/tools/{tool_name}/call`：按路径调用指定工具。
    - 协议端点（MCP 标准）：`/api/mcp/protocol/info`、`/api/mcp/protocol/tools/list`、`/api/mcp/protocol/tools/call`。
- 调用示例：
    ```python
    import requests

    API = "http://localhost:8000/api"

    # 列表
    tools = requests.get(f"{API}/mcp/tools").json()

    # 查看单个工具 schema
    meta = requests.get(f"{API}/mcp/tools/calculator").json()

    # 调用
    resp = requests.post(
            f"{API}/mcp/call",
            json={
                    "tool_name": "calculator",
                    "arguments": {"expression": "1 + 2 * 3"},
                    "caller": "cli-demo"
            }
    ).json()
    ```
- 规范要求：
    - `tool_name` 必须匹配已验证且状态为 valid 的工具名称。
    - `arguments` 必须符合工具暴露的 `inputSchema`，必填字段不可缺失，类型需匹配。
    - 建议传入 `caller` 用于审计。
    - 返回结构：`{success: bool, result: any, error: str|None, execution_time_ms: int}`。调用方需检查 `success` 再读 `result`。

- 在AI应用中调用：
    ```python
    from langchain_core.tools import StructuredTool
    import requests

    def create_remote_tool(tool_info):
        """从远程 MCP 服务创建工具"""
        def call_remote(**kwargs):
            response = requests.post(
                "http://localhost:8000/api/mcp/call",
                json={
                    "tool_name": tool_info["name"],
                    "arguments": kwargs
                }
            )
            result = response.json()
            return result["result"] if result["success"] else result["error"]
        
        return StructuredTool.from_function(
            func=call_remote,
            name=tool_info["name"],
            description=tool_info["description"]
        )

    # 获取远程工具列表
    tools_info = requests.get("http://localhost:8000/api/mcp/tools").json()
    # 创建可用于 LangChain Agent 的工具
    remote_tools = [create_remote_tool(t) for t in tools_info]
    ```

## 16. 上传工具方式与规范（开发者）
- Web 方式：
    1) 进入「上传工具」，填写名称/描述/上传者。
    2) 粘贴源码，先点「仅验证」，修复错误后再上传。
    3) 验证通过后上传，状态应为 valid；如 invalid，可根据提示修正后重传。
- API 方式：
    ```python
    import requests

    API = "http://localhost:8000/api"
    code = """
    from langchain_core.tools import tool

    @tool
    def ping() -> str:
            '''简单连通性检测'''
            return "pong"
    """

    # 仅验证
    validation = requests.post(
            f"{API}/tools/validate",
            params={"source_code": code}
    ).json()

    # 创建/上传（名称需唯一）
    created = requests.post(
            f"{API}/tools/",
            json={
                    "name": "ping",
                    "description": "示例工具",
                    "source_code": code,
                    "uploader": "Alice"
            }
    ).json()
    ```
- 上传规范补充：
    - 工具名称唯一、简短、蛇形命名（如 `text_clean`）。
    - docstring 必须清晰描述用途、参数含义、边界与返回格式。
    - 参数与返回值类型齐全；避免 `*args/**kwargs`；返回值尽量可 JSON 序列化。
    - 避免明文密钥、危险 `eval/exec`、未捕获异常；外部请求需超时与错误处理。
    - 通过验证后，状态应为 valid；若 invalid，按错误与建议修复后重试。
